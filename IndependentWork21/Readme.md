# Звіт про інтеграційне тестування патернів

## 1. Загальна інформація
Тестується взаємодія 4-х патернів: **Singleton** (головний конвеєр `DataPipeline`), **Factory Method** (`StrategyFactory`), **Strategy** (`IProcessorStrategy`) та **Observer** (подія `OnDataProcessed`).

## 3. Короткий висновок по ризиках
1. **Ризик стану Singleton:** У тестах виявлено, що глобальний стан Singleton може "перетікати" з одного тесту в інший (side effects). Для вирішення цієї проблеми було додано метод `ResetForTests()`, який очищує стан та підписників перед кожним тестом. У реальному багатопотоковому середовищі потрібно бути вкрай обережним з модифікацією стратегій на льоту.
2. **Ризик Null Reference:** Завдяки негативним тестам підтверджено, що система захищена від випадків, коли фабрика повертає помилку або розробник забув ініціалізувати стратегію перед запуском конвеєра.
3. **Взаємодія компонентів:** Тести підтвердили DIP (Dependency Inversion) — конвеєр (`DataPipeline`) нічого не знає про конкретні стратегії чи підписників, працюючи виключно через абстракції та делегати.
